// how the gate works

Seven stages between your query and a number.

The fourth is the product. Everything before it is plumbing, and everything after it only runs because the fourth one passed.

01paywall

Challenge

An unpaid read returns 402 carrying x402 payment requirements. No key, no account, no signup.

02verify

Prove funds

The facilitator validates the signed Hedera transfer. Nothing has moved yet, and nothing will unless the data holds.

03fan out

Ask every source

The same query hits every pinned deployment in the family, in parallel, through The Graph gateway.

04the product

Provenance gate

Block lag and age against real chain head, market depth, quorum, and cross-source agreement. Any failure refuses the whole read.

05money

Settle · or refuse

A passing read settles in HBAR. A failing one returns 409 with the payment deliberately unsettled.

06evidence

Sign a receipt

Answer, every source, its block, and the admitting policy are hashed and signed, so the claim can be reproduced by anyone.

07liability

Split · hold back

Revenue routes onchain to the sources that answered. A slice stays unvested and is slashable if the receipt is disproved.

// built on

Three integrations, none decorative.

Remove any one of them and a specific, nameable capability disappears.

The Graph

the data
  • Every source is a pinned deployment id, never a floating name — so a receipt names the exact indexed code that answered.
  • Conformance is byte-identity of the schema IPFS hash from the network subgraph, not a label somebody typed.
  • A shared schema is what makes fanning one query across unrelated protocols mean anything at all.

Hedera

the money
  • x402 over HBAR through the Blocky402 facilitator: verify before the read, settle after it passes.
  • SourcePayouts holds the split, the holdback and the vesting clock, so liability is enforced by a contract instead of by us.
  • Sub-cent fees and fast finality are what make a per-read micropayment sane rather than theatrical.

Bazantic

distribution
  • Fronts this service to buyers who pay in USDC on Base and cannot answer a Hedera x402 challenge.
  • Registered from /openapi.json, so the listing is generated from the service's own contract.
  • Reads arriving that way are marked channel: "resale" in both the response and the receipt.
  • Published recipe: sourcemark-proven-lending-rate-with-hedera-settl (SourceMark + Hedera Mirror Node).

// stated plainly

What this does not do.

The refusal rule would be worth very little coming from a project that oversells everything else.

  • Consent is real; payees are demo source operatorsEvery registry source has EIP-191 consent via POST /v1/consent. Keys come from a dedicated DEMO_SOURCE_MNEMONIC (not the gateway operator, not the public Hardhat phrase). Real indexer teams have not registered production keys.
  • Disputes re-derive against The Graph, then settle onchainPOST /v1/disputes re-queries each pinned deployment at the receipt’s blocks. Match → rejected (no slash). Mismatch → ledger slash and openDispute + arbiter resolveDispute(true) on SourcePayouts when the digest was recordRead. Ambiguous → no slash.
  • Testnet onlyHedera testnet HBAR, a testnet facilitator, and a testnet SourcePayouts deployment.
  • Resale reads are operator-fundedBazantic collects upstream in another currency; sources are still paid in HBAR out of our float. The float is now an auditable ledger on /health.
  • Refusal cannot be bought aroundA caller may tighten a freshness bound. Nothing a caller sends can loosen one past the family policy.

// api surface

GET /v1/reads/:familyThe gate. 402 unpaid · 409 refused and uncharged · 200 with an answer and a signed receipt.
GET /v1/registryThe conformance registry. Adding a protocol is one JSON entry and zero code.
GET /v1/policy/:familyThe freshness policy and the metrics a family exposes.
GET /v1/receipts/:digestThe signed evidence behind an answer, with digest + EIP-191 signature checks and how to re-derive it.
GET /v1/payoutsPer source: earned, cleared, still slashable, already slashed.
POST /v1/disputesRefund a disproved read out of unvested holdback.
POST /v1/consentOpt a source in by EIP-191-signing with its payout address.
GET /openapi.jsonThe machine-readable contract this service is listed from.
